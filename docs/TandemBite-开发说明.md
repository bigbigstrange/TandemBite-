## 2.3.0 奶油手账前端

2.3.1后续调整：按用户要求取消菜品选图裁剪和手动裁剪入口；直接对所选照片等比缩小、持久暂存并上传。上传预览用widthFix和自适应高度显示完整画面，保留大图预览。下文2.2.0裁剪记录仅反映历史版本。

根据用户确认的三种风格预览中的“奶油手账”落地。app.wxss统一主题变量，styles/journal.wxss负责跨页面表面、按钮、标题与短动效；首页和厨房重排。手写字体仅用于标题，正文和金额使用系统字体。导航与功能图标使用Lucide的本地PNG（43个功能图标，另重绘8个Tab图标），不引入运行时图标库。

账本复用现有一次聚合请求。utils/ledger.js在分类汇总里保留整数amountFen；utils/ring.js按实际整数分计算角度和百分比，固定八分类颜色，不从百分比反推金额。components/ledger-ring使用微信原生2D画布，按像素密度绘制；仅数据更新与点分类时重画，没有持续动画循环。零支出不生成占比；画布不支持时仍保留分类金额列表。大金额自动缩小中心字号。

2.3.1移除ui-feedback自定义组件宿主；utils/feedback.js、templates/feedback.wxml和styles/feedback.wxss处理页内反馈。只有tbFeedbackVisible为真才生成提示节点，提示及子节点明确不接收指针事件。全局Page生命周期包装在onHide/onUnload清理计时器，同时保留原表单草稿回调。跨页反馈只留内存、绑定厨房、5秒过期、消费一次。只有业务保存确认成功后排队，失败不庆祝；保留保存请求编号与原有防重复入账机制。没有新增云调用、通知配置、集合或部署要求。

本版合计56项自动化检查。原50项回归通过，新增6项涵盖图表金额／角度／高亮、像素密度与降级、跨页反馈、日期分组及失败不显示成功。微信编译与手机验收状态见验证记录。

## 唯一厨房与账本

- `User.schemaVersion=3`，`User.kitchenId` 指向唯一活动厨房；前端 `activeKitchenId` 仅供旧页面适配，无空间切换功能。
- Kitchen 成员为一人或两人，绑定不是操作前提。菜品、分类、餐单沿用 `coupleId` 归属字段；它不再表示必须两人。账目用 `bookId`，等于同一厨房编号。
- 所有业务读写走云函数，核对当前厨房、成员及整理状态。新版数据集合全部 ADMINONLY；旧厨房/绑定云函数拒绝已升级或正在整理的账号，旧体验者必须更新版本。
- `bootstrap` 对旧结构发起升级；绑定合并双方所有历史；解绑复制完整内容给双方。`KitchenTransition` 保存分页进度，源空间冻结，目标先为 building，复制完成后事务切换双方关系和厨房，原空间为 merged 留作备份。
- 分类按去空格名称合并；不同原始菜品不按名称去重。复制使用确定ID和 originId，重试不重复。同一源菜谱发生不同修改时保留版本并修正餐单引用。
- 账目在解绑后重配时，相同内容的旧账只计一次；同一旧账发生不同修改会暂停，请双方选择保留A/B/分别保留。选择进入 LedgerChange 审计；客户端不能替用户自动选。
- 任一成员重开首页可继续整理。目标完成前不能编辑，失败时源内容保留。真实关系不用于解绑测试。
- 图片引用沿用原 cloud 文件ID，拆分后可能由两个厨房引用，删除菜品不能直接物理删除该图片。

## 账本

金额字符串解析成整数分，日期为 UTC+8 日期字符串。月度默认收入+支出；自定义日期包含两端。categories 筛选只接受八种支出分类，并强制 expense，不能混入收入。列表、统计、导出共用同一查询条件。导出CSV处理中文、引号、换行和公式注入。

创建用 requestId 幂等；编辑、删除、恢复使用版本号。账目与 LedgerChange 在同一事务写入，双方都能修改。汇总按类型、分类聚合，人员统计单独聚合，避免人员数量截断金额。

LedgerEntry现有索引 `book_month_list`：bookId ASC, deleted ASC, dateKey DESC, _id ASC。自定义日期与类别组合需实测云端查询；如控制台报索引缺失，按报错创建复合索引，不能忽略错误返回部分统计。

## 照片与前端

DishAdd 用 chooseMedia 打开相册/相机、压缩照片、上传云存储，再把 cloud:// ID 写到菜品。不把临时HTTPS地址覆盖数据库。选图上限10MB，保存失败后重试复用成功上传的文件；更换照片才重新上传。不自动删除旧文件，后续清理需检查所有副本引用。

厨房概览与竖向点菜分开：点菜沿用左分类、右侧单列滚动和滚动同步。首页、厨房、账本、我的四Tab。轻量CSS动画，不对金额施加动画；标题嵌入OFL字体子集并保留系统回退。

## 当前边界

- 厨房/分类列表最多100项，超过前需补齐分页；账目明细已有分页，统计不会仅汇总当前页。
- 不包含OCR、自动导入支付账单、资金扣款、预算或账户余额。
- 云端源记录和旧图片保留，持续占用存储；未来清理需先导出并检查引用，不自动删除用户记录。

# TandemBite 2.1.1 性能升级（2026-11-03）

本段记录代码和联调中已确认的问题，不把网络、云函数冷启动或免费额度当作已证实的唯一原因。

## 根因与调整

- 多个页面每次onShow都强制串行调用createUser、bootstrap，再单独换头像链接。改为session统一返回当前身份、伙伴、厨房和图片链接，已有账号不再每次重新创建/查询两遍身份。
- 首页原需4～5次手机到云函数的往返；厨房通常6～8次；点菜首次6～7次；账本4～5次（取决于图片链接是否命中缓存）。这些数量由旧代码调用链推导，不是手机网络抓包实测。首页、厨房、点菜、账本现在各用一个view请求，服务端内并行查询，重复权限读取合并，但每次请求仍核对当前成员和厨房。新账号首次初始化/旧数据升级仍可能额外请求。
- 点菜与菜品库复用同一份15秒内存数据；同一并发请求合并。保存后清空缓存，下拉刷新跳过缓存；账本不复用旧金额，每次进入重新读取。缓存不写手机持久存储，不自动合并、修改或删除真实数据。
- 图片链接在同一个view响应中返回，减少手机额外等待；列表图片增加懒加载。新上传照片长边等比缩至1280px，小图不放大；旧照片没有批量重压或替换。
- 菜单不传食材和步骤长正文，详情仍通过原接口读取完整菜谱。滚动分类高亮改为预先测量位置，滚动中仅按scrollTop计算，不再每100毫秒遍历查询布局。
- 修复“选一道菜→搜索另一道→继续选择”丢失之前选择的问题；清空购物车也会清空搜索中隐藏的已选菜品。
- 首次进入首页/厨房显示占位块，未加载前不再显示错误的0元或空厨房；返回页面保留已有内容。账本加载时金额显示等待标识。菜品保存/删除成功后的固定返回等待从1500ms改为400ms。

## 验证与边界

新增tests/performance.test.cjs验证请求次数、并发合并、缓存副本、写后失效、旧请求不能盖过新写入、账本实时读取、日期/分类、聚合接口越权、滚动高亮、照片缩放、搜索选择保持和诊断隐私。全部38项自动化检查通过（含原28项回归）。这些是本地SDK模拟联调，不等于手机耗时测量。

tandem优化代码已部署到cloud1-d6gxpda4073d99c9b，未改套餐、自动续费、并发保底或付费服务。无集合迁移，无真实数据改写。修改前代码备份：上一级checkpoints/before-performance-20261103/code.zip。

本次CLI调用不携带微信OPENID，返回“请通过微信小程序登录”；不能将其1ms拒绝响应当成业务速度。日志查询未取得可用于比较的业务样本；没有关闭身份校验来绕过。开发者工具原生自动化被最小化/同时输入检测拦截，改由用户手机扫码预览2.1.1实测。用户已明确确认“明显顺畅了，页面也正常”。这是手机主观体验与页面可用性验收，没有取得精确秒数、老照片下载耗时或弱网冷启动样本，不能承诺固定倍数提速。

“我的→加载速度诊断”显示本次运行最近8次页面请求的总等待和云端处理时间，可由用户选择复制；不复制账号ID、菜名、照片、金额、备注或完整请求。它不包含图片下载和界面绘制，差值还包括网络、调度和冷启动。数据仅留本次运行内存，不增加外部日志/分析服务。

## 2.2.0 六项体验更新

- 所有页面根节点带 `tb-unified` 和页面类，`styles/unified.wxss` 统一主题、主按钮、照片比例、草稿提示及快捷入口；不替换正文和金额字体，不增添持续运行的动效或前端依赖。
- `utils/drafts.js` 由工厂显式注入 wx/app，仅包装当前表单的 setData，400ms防抖、onHide/onUnload落盘。键为账号ID+唯一厨房+表单类型+记录ID，恢复白名单字段。旧草稿版本与云端不一致时保留旧稿并阻止覆盖。草稿仅存本机，不作为共享业务数据。
- 菜品草稿照片复制到 USER_DATA_PATH/tandem-draft-*，恢复时检查文件可读；缺失时复用已上传的云文件或提示重选，阻止静默丢图。仅在保存成功／主动清除后清理草稿拥有的路径，不删除云图或其他本地文件。上传结果和requestId随草稿暂存，数据库重试无需再次上传。
- 菜品和菜谱编辑传 `expectedRevision`，服务端在事务内比较createTime/updateTime/recipeUpdateTime的最大值。旧客户端不带该可选参数仍兼容。账目继续使用原有整数分、version与事务审计，不走菜品通用写接口。
- 待选餐单保存选择ID、搜索、筛选、分类、滚动位置、备注和requestId，恢复与当前可见厨房菜品交集，成功提交才清除。菜品库另外保存搜索、筛选与滚动位置。滚动时只记内存，离开时落盘，避免逐帧写存储。
- DishList.favorite是双方共享的布尔值，读写沿用服务端成员授权。页面聚合摘要包含favorite；收藏置前、单独筛选；常做按orderCount降序。新客户端创建餐单带 `countDishes:true`，事务同时增加唯一菜品的orderCount；幂等重试不重复增加。旧客户端未带标记仍使用原有计数路径。合并同源同内容菜品保留favorite并集和最大orderCount。
- LedgerEdit新增金额定位、常用备注、保存并继续；成功后才换requestId，保留类型／分类／日期；失败保留原内容。原生裁剪通过 `wx.cropImage({src,cropScale:'4:3'})`，缺少该API时保留原照片并提示升级后可调整裁剪；详情用wx.previewImage，不引入付费图片服务。

本次无数据库集合／结构迁移，仅需部署tandem及发布2.2.0前端。云函数已部署，状态Active；发布流程与真机待验项目见手机使用说明和验证记录。自动化检查合计50项，包括原38项回归与12项新体验检查。
